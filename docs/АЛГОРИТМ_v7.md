# Алгоритм v7 — как считается подсказка

## 1. Конвейер (один проход по базе, `pipeline/passV7.cjs`)

Для каждой точки решения на префлопе (`lib/spots.js`, контексты как в v6: RFI / ISO / VSO / VS3 / AI) копятся:

| Что | Ключ | Зачем |
|---|---|---|
| **EV** `[n, ср., σ, nFA, ср.FA]` | `когорта\|TBL\|страта\|стол+баунти\|поз\|поз.опп\|стек\|L/R\|C\|действие\|группа.опп` | частоты действий, EV от фолда, доля «все сфолдили» и банк в этом случае |
| **HC** `[n, ср., σ]` | то же + `h<0..168>` / класс-12 / `*` | EV продолжения для руки (только вскрытия) |
| **RS** — 169 счётчиков | `группа\|O/VSO/VS3\|страта\|стол\|поз\|стек` | диапазон пушащего по вскрытиям |
| **RC** — 169 счётчиков | `группа\|страта\|стол\|поз\|поз.пушащего\|стек\|R1/R2/R3` | диапазон колла олл-ина |

- Когорты: `T` — топы (половина A при `OOS=1`), `F` — поле, `g<группа>` — группа игрока (top / areg / preg / fish).
- Обобщённый уровень помечен `~`: семейства позиций EP / MP / CO / BTN / SB / BB.
- `R1/R2/R3` в споте AI — каким по счёту рейзом был олл-ин: пуш первым, поверх опена, поверх 3-бета.

## 2. Движок (`engine/engine_v7.js`): варианты действия и EV от фолда

1. **Фолд = 0** (точно).
2. **Пуш** (первым, против лимперов, поверх рейза): по каждому, кто ещё в раздаче, суммируется P(он коллирует первым) × [эквити(рука против его диапазона колла) × банк − риск] + P(все сфолдили) × банк.
   - Частота колла берётся из споте AI с его стороны и поправляется на блокеры.
   - Диапазон: точный ключ, сглаженный обобщённым (Дирихле, α = 12). Если данных нет — «лучшие p%», где p учитывает, что игрок уже сузил диапазон своим рейзом.
3. **Колл олл-ина:** эквити против диапазона пуша из того спота, где пушили (O / VSO / VS3), × итоговый банк − колл. При коллерах до нас — приближённо.
4. **Остальные действия при известной руке:** P(FA) × банк + (1 − P) × [слой HC (рука → класс → обобщённо, топы → поле, стягивание) − сдвиг вскрытий].
   - Надёжно только при n ≥ 400.
   - Если по руке данных нет, EV не выдумывается (правило владельца «нет данных → не играем»). EV диапазона показывается справкой.
5. **Частоты топов:** доли действий топов в споте известны по всем раздачам, карты для этого не нужны. Они раскладываются по рейтингу рук: самым сильным — самое агрессивное действие, хвосту — фолд. Отсюда «что топы делают с этой рукой».

**Как выбирается совет:**
1. Надёжный EV лучше фолда.
2. Иначе — действие по частотам топов.
3. Иначе — фолд.

Глубже 15 bb пуш не перебивает частоты топов, хотя его EV считается точно. Иначе модель тянула бы к пушам только потому, что пуш можно посчитать.

**Вердикт фактическому действию:**
- «лучшее» / «совпадает с базой»;
- «близко (в пределах шума)»;
- «вероятно хуже» — когда оценка вашего действия ненадёжна;
- «ошибка −X bb»;
- «нет данных».

## 3. Проверки (синтетика 400 тыс. раздач, карты героя известны всегда)

| Проверка | Результат |
|---|---|
| Оценщик 7 карт: частоты категорий, AKo против 76s точным перебором (57,75%) | `tests/test_cards.js`: 16/16 OK |
| Ошибка EV класса руки (неолл-ин), v6 → v7 | 1,76 → 1,03 bb |
| Шум итога в спотах пуша | σ 7,31 → 4,07 bb (данных нужно в 3,2 раза меньше) |
| Прогноз пуша и колла олл-ина против факта | 22 из 29 групп в пределах 95% ДИ |
| Блайнды: v6 советует фолд при выгодном действии | 17 из 26 пар |

Синтетика — грубая модель покера. Её задача — поймать ошибки формул, а не дать числа для реальной игры. На реальной базе в 250 раз больше данных, и редкие споты (пуш против 3-бета) станут плотнее.

## 4. Что не решено и почему

- **EV конкретной руки в неолл-ин спотах по датамайнингу честно не восстанавливается:** карты видны только на вскрытии. Есть три выхода:
  1. ваши собственные раздачи (в MDA Lab 109 тыс. рук, карты героя видны всегда) — несмещённый слой «рука → EV» для вас;
  2. румы или выгрузки, где видны все карты (если такие есть в базе — скажите);
  3. частоты топов (как сейчас).
- ICM не учитывается: везде chip EV. Нужна стадия турнира: баббл, ФТ.
- Постфлоп в v7 пока не переделан: слои FLOP / TURN / RIVER из v6 смещены так же, как HC.
- При мультивее в колле олл-ина эквити считается произведением — это приближение.

## 5. Запуск на вашей базе (Windows, папка Backing `D:\маининг\реплеер`)

```
cd <папка replayer-MDA>
set BACKING_DIR=D:/маининг/реплеер
node pipeline/passA_v7.cjs                 :: статы игроков по половине A (~1 ч)
node pipeline/tops_v7.cjs                  :: топы по половине A
set OOS=1
node --max-old-space-size=12288 pipeline/passV7.cjs   :: модель по половине B (~1,5–3 ч), чекпоинт после каждого архива
:: после падения: set RESUME=1 и запустить снова
```

- Архив `2608-PS-.rar` пропускается сам (`SKIP`).
- Результат — `pipeline/out/model_v7.json`.
- На синтетике: 400 тыс. рук за 0,8 мин → 100 млн примерно за 3 ч на одном ядре.
- Группы игроков берутся из `players_cl2.json` Backing.
