# План доводки префлопа (согласован с владельцем 19.11.2026)

Цель: в разборе турнира по каждому префлоп-решению героя — лучшее действие по фишкам против конкретных игроков
(класс + личные статы при достаточной выборке), лучше GTO там, где это подтверждено базой. Никогда не советуем
действие в минус или около нуля. Постфлоп — после префлопа (см. ПРОДОЛЖЕНИЕ.md, постфлоп-этап).

## Уже сделано
- Только плюсовые действия: EV руки (или средний EV топов/регов действием в споте) > фолда, иначе другое плюсовое / фолд.
- Олл-ин: порог перевеса 0.5 bb и 2% риска (дисперсия); доколлы — трое в игре; частота колла олл-ина — тот же класс →
  обобщённые позиции → соседние стеки → пул; без заглушки 15%.
- Сайзинги: самая частая корзина топов с реальной суммой «до», распределение размеров топов в споте.
- Частоты руки с фолдом (оценка), частоты регов и топов словами.
- Параллельный конвейер (потоки, низкий приоритет, слияние состояний), режимы «фон»/«максимум».
- Новые румы WPN и iPoker: перевод, статы/кластеры/топы, слой рума и ячейки по картам героя (D…) в модели.
- Бот против GTO: совпадение по узлам HRC, грубые отклонения, потеря на фолдах.

## Топы (решение владельца 19.11.2026)
- Топ-1: рег-кластер + ≥ 10 000 рук + винрейт ≥ 8 bb/100 в обеих четвертях половины отбора (pipeline/winq.cjs →
  pipeline/tops_q.cjs). Отобранные по половине A меряют раздачи половины B и наоборот — удача отбора не попадает в модель.
- Топ-2: то же, винрейт ≥ 5 (ячейки «U» в модели, слой tops5 в размерах). Берётся, если у топов-1 в споте < 100 рук
  (по всем действиям спота вместе); затем реги.
- Порядок работ: владелец догружает новую базу → статы/кластеры новой базы → ТОПЫ_ОЦЕНКА.cmd (таблица: минимум рук ×
  винрейт → топов и рук) → владелец подтверждает пороги → пересчёт модели и размеров одним .cmd → проверка.

## Дальше, по порядку
1. Проверка после пересчёта новых румов: доля повреждённых, сводки модели, повтор бота против GTO, проверка турниров.
2. Честные данные с картами при любом действии (iPoker, свои истории): точный EV и частоты руки с фолдом там, где выборки
   хватает; замер точности нынешней оценки фолдов (в процентных пунктах).
3. Слой рума в движке: свои топы/реги рума первыми, остальные — для редких спотов.
4. Отклонения от GTO — только подтверждённые: EV нашего действия по базе > 0 и > EV GTO-действия с запасом.
   Отчёт: «эксплойт подтверждён / не подтверждён / мало данных»; не подтверждённое → GTO-действие.
5. Точный EV пушей против GTO (эквити против диапазонов колла HRC) — закрыть «не оценено» в боте.
6. Личные статы: минимум ситуаций (по умолчанию 30), вес личных статов показывать в совете; ответы соперников по классу и
   личным статам для 3-бета, 4-бета, колла, сквиза (пересчёт лайнапа).
7. EV по дереву решений: 3-бет с учётом нашего ответа на 4-бет, колл с реализацией эквити после флопа (меряется по честным
   раздачам).
8. Уверенность вместо жёстких порогов: плавное стягивание к уровню выше; совет — если нижняя граница плюса > 0 и > альтернатив.
9. Сайзинги точнее (сделано 19.11, пересчёт — САЙЗИНГИ.cmd): своя позиция (SB ≠ BB), точный стек (запас — только соседний
   глубокий; средние и короткие — только свой), позиция открывшего, формат, размер стола, изо — по позиции и числу лимперов,
   сквиз — по числу коллеров, **класс соперника** (рег / нит / фиш): опен — по лайнапу позади (сколько фишей среди тех, кто
   ещё ходит: 0 / 1 / 2+), изо — по первому лимперу, 3-бет/сквиз/4-бет — по рейзеру. Класс известен — берутся
   только ключи против него (свой рум → соседний глубокий стек → все румы); если там у топов < 100 рук — «размер: нет
   данных» (общий размер и запасные значения не подставляются). Класс неизвестен — размер топов в споте против всех.
   В совете: «Размеры у топов здесь против фиша: …». Позже: стадия (ICM).
   Решено (19.11): у 3-бета / сквиза / 4-бета игроков позади НЕ учитываем — ни в EV, ни в фолдах, ни в размере
   (споты дробятся, данных не хватит). Учитывается только класс рейзера; лайнап позади — только у опена.
   Лайнап: ответы на опен у не-блайндов сейчас одной группой (BTN = CO = HJ…) — разделить при пересчёте лайнапа.
10. Модель поля (20 кластеров) + наилучший ответ полю + самоигра; проверка на отложенной половине базы.
11. Ускорение: кэш решений (двоичный), все шаги за один проход, двоичные состояния; проверки на 5–10% базы.
12. База 2025 года (когда будет), с меньшим весом и проверкой, улучшает ли прогноз на 2026.
13. Формат турнира (фризаут / PKO / Mystery) — уже в ключах, топах, лайнапе и EV баунти. Дыра: у WPN и iPoker размер
    баунти в историях не записан. На модель это не влияет: в данных EV считается в фишках, размеры баунти не используются
    ни для одного рума; баунти добавляется только в совете — по вашему турниру (PokerStars, размеры видны).
14. Mystery Bounty: в модель — только раздачи, доказанно сыгранные до призовой зоны (passV8, с 19.11.2026; у WPN/iPoker
    стадию пока не узнать → их Mystery целиком вне модели). Старая база PS и статы/топы — исправятся при следующем полном
    пересчёте (статам нужен ход турниров из прошлого прохода). Стадию для WPN/iPoker — по уровням блайндов и среднему стеку.
15. После каждого пересчёта — калибровка (прогноз против факта), бот против GTO, турниры владельца.

## Правила интерфейса (не меняются)
Советы только герою; после фолда героя — ничего; размеры в bb; размеров с 0% нет; матриц нет; таблица действий:
EV руки / EV базы / топы / реги / фиши (фиши — только для сравнения); GTO — рекомендация в скобках; основной ответ — по
базе топов и регов.
